# 安装 登录和权限问题排查

适用于三家平台。先确认所选平台、CLI版本、当前账号/企业及失败发生在哪一步。只输出错误类别、缺少能力和可读提示；不要把完整认证JSON、URL中的授权code、cookie或token发给别人。

## 不同阶段的成功判据

| 阶段 | 可以确认的事 | 尚不能确认的事 |
|---|---|---|
| CLI --version成功 | 当前终端找到可运行的程序 | 用户已登录、能读文件 |
| 应用配置完成 | CLI具备对应应用或凭证配置 | 已有本人身份和文件权限 |
| auth-check明确authenticated=true | CLI能识别所选用户授权状态 | 任何目标文档都能读取 |
| 目录/搜索有结果 | 发现有限候选 | 已读取正文、所有分页完成 |
| 选定文档正文同步成功 | 这批选定正文当前可读取 | 图片、附件、未选文档已覆盖 |
| build/verify成功 | 用户所选产出文件已生成且引用检查通过 | 内容语义、Office兼容性或绩效结果已被独立证明 |

## 安装找不到命令

1. 在与Agent相同的终端和账号下检查，不在另一个用户账户或管理员终端中替它安装。
2. macOS/Linux可用command -v检查；Windows用Get-Command。重新打开终端/Agent，让新的PATH生效。
3. npm安装报EACCES时，优先采用用户级Node/npm环境或公司允许的安装器；不默认sudo npm install或更改整个系统目录权限。
4. Windows的python可能指向Microsoft Store启动别名，可用py -3检查实际Python；venv命令见installation.md。PowerShell脚本被策略拦截时先走企业允许方式或直接运行python脚本，不修改全局执行策略。
5. 二进制无法启动时核对CPU架构和OS支持；CLI当前版本和项目支持范围分别确认。官方新参数不一定存在于旧二进制。

## 下载超时 代理和证书

仅因网络超时重试同一下载一次。使用用户已配置的可信代理，让代理在实际执行CLI的终端生效；不要假定其他人机器有proxy_on函数，不把本开发者的代理地址写进Skill。公司网络策略阻断时由网络管理员处理。

TLS/SSL证书错误不是授权失败。检查系统时间、企业代理根证书和受支持的证书存储。不要用curl -k、关闭TLS验证或把令牌贴到其他网站。npm镜像只使用官方明确提供或企业认可的来源；不要把全局registry改到未知地址。

若官方源和企业允许的镜像均不可用，保留清楚的错误并停在安装阶段；可继续处理本地资料或查看预生成示例，不假装平台已接通。

## 登录流程失败

- 只保留一个当前登录流程。记清当前进程、当前链接/二维码、服务端给出的有效期；敏感device_code只在进程/当前会话中临时保管。
- 浏览器成功但CLI失败时，检查回调是否回到同一台机器、原进程是否还活着、分步流程是否还没恢复轮询、账号/组织是否选错。
- 取消、过期、拒绝或已结束的流程不复用；先结束旧流程，重新生成一次当前链接并让用户完成。
- 网络失败、认证锁、凭据存储错误和未知回包不能被简化成“未登录”；auth-check此时保留authenticated=null。
- 不默认退出其他账号、清空密钥链、auth reset、重建应用或共享他人token。具体恢复见所选平台指南。

## 权限不足分三层核对

1. **账号和组织**：CLI代表的是谁，是否为需要读取个人资料的user身份，是否处于正确企业；bot身份不是本人身份。
2. **应用或行为能力**：应用scope、组织CLI开关、PAT授权或应用可用成员范围；明确缺哪个再申请哪个，不批量申请全部业务域。
3. **具体文档访问**：同一账号在原平台能否打开该文件/目录；文件拥有者或管理员按平台流程授予阅读权限。

有权限列目录仍可能无权读正文，某篇无权限也不能推出全部平台不可用。拿一篇用户允许的文档做最小验证；授权变更后只重试失败的选定项目。没有变化时不循环重试。

不把“换成更高权限账号”“公开文档”“发消息给全部管理员”“启用全量聊天存档”当作默认解决方案。需要申请时给用户说明该做哪一步，平台内部申请由用户完成。

## 错误类别

review.py auth-check与平台同步只给出保守分类：

| 类别 | 下一步 |
|---|---|
| not_installed | 按对应安装指南装所选CLI |
| configuration_required | 完成应用/凭证初始化 |
| login_required | 新建一次用户授权，成功后复查 |
| missing_scope | 核对实际读取需要的scope，应用端批准后补授用户权限 |
| organization_blocked | 用户走官方组织访问申请，管理员处理 |
| behavior_authorization_required | 钉钉PAT拦截，按所选只读行为授权；不能靠重复扫码解决 |
| access_denied | 核对账号、scope与文档ACL；自动分类不能总能区分这三者 |
| credential_repair / indeterminate | 先检查凭据可读性/锁，按官方迁移或修复指引预检 |
| network_timeout / diagnostic_failed | 检查网络、证书或锁；不能当作已确认未登录 |
| unsupported_cli | 对照本机--help与官方版本说明，处理契约差异 |
| unknown_response / unknown_error | 保留未知，不能凭退出码0、success或搜索结果推断已接通 |

这些分类用于提示下一步，不能代替平台管理员判断。未知业务错误的原始文本不被写进项目日志，避免泄露认证数据；需要人工诊断时只在用户本机查看并脱敏。

## 仍读不到资料时

用户可选择缩小资料范围、改用本地导出或只先整理已成功读取的部分；必须说明失败来源和覆盖缺口。不把旧缓存、搜索高亮、目录标题或空正文当成本次成功读取。平台成功不会自动给本人归功，仍需依据具体分工、完成状态和事件日期核对。
